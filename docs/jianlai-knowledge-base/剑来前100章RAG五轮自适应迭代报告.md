# 《剑来》前 100 章 RAG 五轮自适应迭代报告

## 范围与验收原则

本报告对应《剑来》前 100 章（数据库 chapter index 0--99）的五次连续 ReAct 实验。每轮均先查看上一轮的严格 Benchmark 和失败样本，再决定下一轮；并非预先排定五个方案后机械执行。原始机器可读记录位于 `artifacts/jianlai-rag-evaluation/react-round-1-candidate-pairs.json` 至 `react-round-5-pair-anchored-retrieval.json`。

Benchmark 2.0 的 8 条关系金标检查关系类型、方向、章节和 evidence 端点词；9 道检索题必须命中指定章节，不将人物同场出现算作正确关系。规则只可用于候选窗口、实体/别名召回和 evidence 校验，不能据此生成关系边。报告不保存大段小说正文或任何密钥。

## 五轮闭环结果

| 轮次 | 上轮观察与本轮假设 | 实际改动 | 真实结果 | 复盘后决策 |
| --- | --- | --- | --- | --- |
| 1 | 宽窗口模型把关系预算消耗在旁支人物，尝试缩小待审对 | 由已知人物在证据中共现产生候选对，并硬限制宽窗口输出 | 406.4 秒；81/37 节点/边；人物连边 44.44%；关系召回 37.5%；检索 22.22% / 0.0778 | evidence 支持率达到 100%，但合法边被候选榜排除，人物连边下降；撤销硬限制。 |
| 2 | 第 1 轮漏掉候选榜外关系，尝试仅提示模型优先审查 | 候选对不再过滤输出；为帮助、引荐、保护、同行等信号加权 | 252.3 秒；81/41；人物连边 52.78%；关系召回 25.0%；检索 22.22% / 0.0778 | 仅加强 Prompt 没有稳定提升，不能继续盲调 Prompt。 |
| 3 | 宽窗口可能漏审关键人物对，验证独立模型核验 | 对每个宽窗口前两名候选对独立调用模型；模型仍须给出类型、方向和原文 evidence，允许“无关系” | 476.9 秒；81/41；人物连边 52.78%；关系召回 37.5%；角色关系 evidence 支持率 92.31%；检索 22.22% / 0.0778 | 调用成本明显上升，关系召回没有超过可靠基线；不再扩大二次模型调用。 |
| 4 | 图存在并不表示关系问句能召回正确原文，检索才是主要瓶颈 | 使用问题中的规范实体和已审别名召回原始正文 chunk，再由现有 reranker 排序 | 不重建图；81/41；关系召回 37.5%；检索 66.67% / 0.5093 | 这是唯一大幅且稳定的增益。剩余失败集中在双实体和别名同时出现的题目。 |
| 5 | 单实体锚点仍引入单边噪声，验证双实体/别名共同出现的正文候选 | 在单实体锚点前，加入 `ENTITY_PAIR_ANCHORED`：仅当同一原文 chunk 命中两端规范名或已审别名时加入候选；不生成任何图边 | 不重建图；81/41；关系召回 37.5%；检索 88.89% / 0.6574；禁止关系 0；剧透越界 0 | 保留。命中从 6/9 增至 8/9，仍需单独处理齐静春的别名/实体覆盖问题。 |

“检索”列依次为严格 Recall@5 / MRR。第 4、5 轮是检索层变更，沿用同一份已经重建的图谱，因此节点、边和关系指标保持不变；这不是把图谱未提升伪装成提升。

## 第五轮实现与边界

`KnowledgeServiceImpl` 先解析问题中出现的已审图节点和别名，再从阅读边界内的原始 `KnowledgeChunk` 召回同时包含两端实体的片段，来源标记为 `ENTITY_PAIR_ANCHORED`，再交给既有向量、关键词、图 evidence 的统一 reranker。它不从“共同出现”推导 `HELPS`、`GUIDES` 或其他关系，也不写入数据库图谱。

这一设计带来了两项可验证结果：

- 刘羡阳--陈平安的帮助题从第 3 名升至第 1 名；黑衣少女（宁姚）--陈平安题命中第 3 名。
- 陈平安--宋集薪的邻里题命中第 3 名；其余已有命中的阮师傅、龙窑、顾粲和防剧透题没有退化。

## 当前可靠结论与未解决项

最终可靠收益在检索层：相对第 3 轮，Recall@5 从 22.22% 到 88.89%（+66.67 个百分点），MRR 从 0.0778 到 0.6574。实体/别名锚定和双实体联合锚定均为原文召回增强，而非以规则伪造关系。

图谱仍不是完成态：严格关系召回为 37.5%，语义人物关系召回为 42.86%，人物连边率为 52.78%。金标尚缺刘羡阳帮助陈平安、齐静春引导陈平安、陈平安保护/帮助宁姚、阮邛--阮秀亲子和陈平安居住泥瓶巷。第 3 轮的独立核验已说明，继续叠加模型调用不能保证改善这些问题。

唯一未命中的检索题是“齐先生在前 100 章如何引导陈平安”。后续应先审计该别名是否以可见、已审的实体别名落库，以及第 21--23 章是否被切成两端不共现的 chunk；只有确认数据覆盖后，再测试针对证据邻接 chunk 的召回。不能直接按金标写入 `GUIDES` 边。

另有一条第 59 章 `KNOWS` 边的 evidence 未完整支持端点，且若干 `PARTICIPATES_IN` 边的 evidence 不够干净；该问题已保留在第五轮 JSON 的 `unsupportedEdges` 中，未借本次检索优化掩盖。最终禁止关系为 0、别名污染为 0、防剧透越界为 0。
