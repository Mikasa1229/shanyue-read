# 小说智能体计划全量验收报告

> 审计日期：2026-07-31
> 审计范围：`docs/novel-agent-architecture-plan.md` 全文，包括 Phase 0--4、架构约束与第 12 节验收标准。
> 审计结论：**核心实现已大范围落地，但不能判定计划书的全部任务已完成；最终验收尚未通过。**

> 注：第 1--9 节保留 2026-07-31 的历史审计快照；部署边界和标准端口的后续复验结果见第 11 节，不能把历史 `8096` 结论当作当前运行态。

## 1. 审计方法与证据标准

本报告不以计划书和实施状态文档中的自述作为完成证据，而是按以下优先级核验当前工作树：

1. 后端、前端、数据库迁移、Docker 与启动脚本中的实际实现。
2. 自动化测试、前端生产构建、Compose 配置与静态检查的实际输出。
3. 当前本机容器、端口和 HTTP 接口的运行态结果。
4. 只有真实外部提供商、第三方 SDK 或授权语料才能证明的项，必须保留外部验收记录；源码和 Mock 测试不能代替。

状态定义：

| 状态 | 含义 |
| --- | --- |
| 已验证 | 已找到实现，且本次自动化或运行态证据能够支撑完成结论。 |
| 已实现，待外部验收 | 源码和本地测试支持，但必须依赖真实模型、外部服务或授权语料才能完成验收。 |
| 未通过 / 未完成 | 当前运行态或证据直接与计划要求冲突，或者关键交付没有完成。 |
| 风险 | 不阻断当前构建，但会影响可维护性、部署稳定性或将来验收。 |

## 2. 总体结论

### 2.1 结论摘要

- Phase 0--4 的绝大多数代码、迁移、前端界面、自动化测试和基础设施配置已经存在。
- 后端全量回归、前端生产构建、Docker Compose 配置检查与差异格式检查均通过。
- 当前部署/运行实例不符合 Agent 直连隔离要求：`http://localhost:8096/api/agent/infrastructure` 实际返回 `200`，而计划要求绕过 Gateway 的浏览器 API 请求必须被拒绝。
- 真实模型质量、外部 Reranker 压测、真实授权语料图谱质量和独立第三方 MCP SDK 的部署态验收仍没有本次可复核证据。
- 标准后端服务和前端开发服务当前没有在预期端口运行，无法完成真实登录态的端到端产品验收。

### 2.2 最终判定

**不通过“计划书所有任务均已完成”的最终验收。**

原因不是缺少主体功能代码，而是有一项实际部署安全边界失败，且计划明确要求的外部/真实场景验收尚未执行或未提供可复核证据。

## 6. 阻断最终验收的问题

### P0：当前 Agent 实例允许绕过 Gateway 直接访问

**计划要求**：Agent 端口不能允许浏览器直接伪造用户身份；Gateway 清洗外部头后注入唯一可信身份，Agent 必须验证 Gateway 转发 Secret。

**实际结果**：

```text
GET http://localhost:8096/api/agent/infrastructure
HTTP 200
```

**源码状态**：最新源码中的 `AgentGatewayAccessFilter` 已规定缺失或不匹配 `X-Agent-Gateway-Token` 时返回 `404`。因此问题很可能是 `8096` 的残留/旧实例未按最新源码和非空匹配的 `AGENT_GATEWAY_TOKEN` 重新部署，而不是当前源码缺少防护。

**影响**：在未替换该运行实例前，不能声称完成计划的 Gateway 身份边界与未登录数据隔离验收。

**必须完成的修复验证**：

1. 为 Gateway 与 Agent 设置相同且非空的 `AGENT_GATEWAY_TOKEN`。
2. 重启/替换当前 Agent 与 Gateway 进程，确保使用最新构建产物。
3. 运行 `scripts/validate-agent-deployment.ps1`。
4. 保留结果，其中应同时证明 Agent 健康、Flyway V26--V29 和直连浏览器 API 返回 `404`。

### P1：真实模型、真实 Reranker 与授权语料验收缺失

以下验收不能由当前单元测试或 Mock 替代：

- 真实模型对引用、拒答、剧透控制、角色访谈和推荐的质量。
- 配置外部 Reranker 后，真实提供商排序、故障回退和至少 50 请求压测的 p50/p95、错误率、Prometheus 指标变化。
- 版权明确的复杂语料中，同名角色消歧、线索回收、事件因果与按阅读边界裁剪质量。
- 真实故障（模型、Reranker、Milvus、Neo4j、书源）下的用户可见降级与主阅读链路可用性。

仓库已有可执行流程：`docs/novel-agent-external-validation-runbook.md`。在没有这些外部证据时，最终验收必须保持未完成。

### P1：第三方 MCP SDK 的部署态互操作证据需要保留

内部 MCP 的 JSON-RPC、工具白名单、Schema 校验和生命周期测试已存在且后端测试通过。但最终交付仍应保存一份独立 MCP SDK 对部署实例的实际初始化、`notifications/initialized`、`ping`、`tools/list` 和只读跨服务调用记录（脱敏后），以证明不是仅对仓库内测试客户端兼容。

### P2：完整业务链路当前未在标准端口运行

本次 `scripts/check-status.ps1` 显示中间件健康，但 8080--8086 与前端 3000 均未运行。这个状态不否定源码完成度，但不能作为产品层面的端到端验收环境。

## 7. 非阻断风险与改进建议

### 7.1 Maven 插件版本未固定

本次 Maven 构建成功，但给出警告：根 `backend/pom.xml` 中 `maven-compiler-plugin` 与 `maven-surefire-plugin` 未显式声明版本。当前 Maven 自动选择了可兼容版本，未来 Maven 升级可能产生不一致的编译或测试行为。

建议在父 POM 的 `build/plugins` 中显式锁定两个插件版本，并在 CI 中使用固定 JDK 与 Maven 版本。

### 7.2 当前工作树包含大量未提交改动

本报告仅审计当前工作树，并未假定这些改动已提交、已审阅或已部署。最终交付前应：

1. 整理变更并进行一次独立代码审查。
2. 在干净环境执行全量构建、迁移和外部验收。
3. 将验证产物（脱敏的脚本报告、指标摘要、评估结果）与提交版本绑定。

### 7.3 真实运行态与源码可能漂移

本次 P0 问题已经证明正在运行的 `8096` 实例不是可以直接等同于当前源码的部署版本。建议发布流程增加：构建版本号、健康检查、Gateway 直连边界检查、数据库迁移版本检查和部署后 smoke test。

## 8. 推荐的最终收尾顺序

1. **部署边界修复**：替换 Agent/Gateway，设置并轮换 `AGENT_GATEWAY_TOKEN`，通过 `validate-agent-deployment.ps1`。
2. **恢复端到端环境**：启动 Gateway、User、Novel、Agent 与前端，使用真实登录用户检查悬浮入口、Agent 中心、阅读上下文、隐私隔离和用户可见降级。
3. **外部模型验收**：准备原创或授权小说 fixture，配置真实模型与 Reranker，执行 `validate-agent-reranker-load.ps1`，保存脱敏指标报告。
4. **MCP 互操作验收**：使用独立第三方 SDK 对部署实例执行完整生命周期及只读工具调用，保存脱敏请求/响应证据。
5. **质量门禁验收**：提交真实模型输出到管理员答案评估接口，确保没有引用、剧透、图谱、工具安全和推荐溯源失败项。
6. **发布基线固化**：固定 Maven 插件与构建工具版本，提交变更，建立可重复的 CI/CD 验收任务。
